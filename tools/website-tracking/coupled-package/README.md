# Coupled package composer

Offline engineering only. `composeCoupledPackage()` derives the eight contact/guard reconciliation members on the selected full admission client, rental-copy, frame and fenced receiver ancestry. It returns a private in-memory candidate and a redacted public summary. It never installs, contacts a provider, updates original fixtures, changes canonical action settings, or issues a complete-profile certificate. Every output is HELD and deployment prohibited.

Run the focused public/synthetic checks from the repository root:

```powershell
$env:BSRE_SOURCE_ROOT=(Resolve-Path .).Path
node --test tools/website-tracking/coupled-package/test-compose.mjs
```

`BSRE_SOURCE_ROOT` identifies the accepted source checkout for these tests only. Source files are read and hashed; the source checkout is never written. The test runner creates and removes isolated temporary synthetic files. No actual captured body, destination identity, approval or private path belongs in this directory.

## Input contract

Call `composeCoupledPackage(input)` with:

- `source_root`: local reviewed source checkout containing all eleven pinned builder/runtime modules. All module bytes are verified before and after derivation. No injected client generator is accepted.
- `original`: exactly30 `{path, bytes: Buffer}` records relative to the original plugin tree. The canonical public member map, immutable archive declaration and receiver original pin are fixed in code. `readRegularTree(root, names)` rejects links/junctions, redirects, unsafe paths and bounded-size violations.
- `provenance`: `original_zip_sha256` and `member_map_sha256` from the immutable original record. Optional `original_zip_bytes` must match the pinned archive digest. If absent, the explicit `ORIGINAL_ARCHIVE_BYTES_NOT_REHASHED` hold remains; the declared digest is never described as a fresh archive-byte verification.
- `receiver_original`: immutable original receiver bytes. The companion is built by the no-mail builder once, which already includes status and admission before appending its runtime. It remains separate from the plugin and from the deployed receiver.
- `captured`: exactly30 raw private capture records, in the same relative format. These are compatibility evidence, never a replacement original baseline.
- `capture_binding`: a private independently reviewed `members` path-to-digest map for all30, nonempty opaque `review_ref`, and exact `reviewed_counts` for each of the seven contact-bearing members. Each count record has exactly `matcher`, `whatsapp`, `telephone`, and `display`. Review counts and target digests must come from the retained private evidence; deriving them from arbitrary supplied bytes is not review authority.
- `identity`: private `from_digits`, `to_digits`, `from_display`, `to_display`. Display forms must contain the identical digits with a leading plus and optional spaces. This contract is restricted to the approved calls/WhatsApp identities. Typed telephone/WhatsApp/display changes and one client recognition literal are the only allowed capture edits. All other bytes must equal the original.
- `native_binding`: private `captured_body_sha256` and `expected_body_sha256` matching the captured and final hub respectively. This supplies an expected-body binding only. Runtime/native acceptance remains pending regardless of values supplied here.
- Optional `selected_outputs`: independently constructed G1–G5 `{path,bytes}` records at the exact inventory paths, plus independently reviewed `selected_output_pins`. Only the three expressly selected existing G2/G3 members can override baseline members; the owned contact/client/frame/guard/receiver outputs cannot be replaced. Set `require_all_selected_outputs:true` to reject any missing selected inventory member or unsupplied G2/G3 override. Pin equality binds bytes; it does not establish the external module's semantic acceptance or integration correctness.

The full selected inventory is62 outputs. This bounded composer owns31 outputs including the separate receiver companion, and requires34 externally supplied additions/overrides (three override existing original members). Without those inputs it returns `PARTIAL_HELD`, naming the missing relative output paths. Even with all entries supplied it returns only `STRUCTURAL_HELD`, with `complete_profile_certified:false`. G3–G5 acceptance, independent integration review and the release holds are never inferred from file presence.

## Preserved derivations

The client starts from the immutable original through reload, receipt, attribution, purpose and retention-admission. A separately called contact-compatible admission builder must produce exactly the same final bytes. The original purpose-only contact adapter cannot replace it. Reversing the final overlay recovers the complete precontact candidate byte-for-byte.

The rental template first receives the separately pinned two-literal copy derivation, then the contact overlay. Its removed noscript contact sentence stays removed, reducing that output's display edit count by one. Every other contact member has independently bound raw-capture and candidate overlay counts. The final hub digest patches exactly the known guard constant; all other guard bytes reverse to the original. All eight members have ordered ancestry, digests, exact permitted ranges and reverse-verification records. All22 unchanged captures are covered separately.

The frame parent is derived from its original builder; the runtime child stays unchanged. The receiver is a held companion, with its immutable deployed original unchanged. Canonical conversion policy remains action7873290954, Secondary, One, AED0 fallback and no duplicate GA4 receipt import; this composer contains no live conversion configuration or activation operation.

## Private output and holds

`result.files` and `result.private_manifest` are PRIVATE when actual identities/captures are used. Never commit them or log them. Only `result.public_summary` is suitable for a redacted summary; it omits contact bytes, target/candidate identity hashes, review references and machine paths. Fixed error codes omit underlying input and filesystem values.

`writeHeldPackage(result,{destination,input_roots,visibility:'PRIVATE_OFFLINE_ONLY'})` writes only to a new directory with an existing regular parent, disjoint from every provided original/capture/source input root. Pass all actual input roots; no installer/site destination is authorized. It verifies output hashes before creating a temporary sibling, writes private manifests last, and renames the completed inert directory. Existing destinations are rejected. Failure removes only its checked newly allocated temporary sibling. This is an offline package writer, not a deployment mechanism.

Open acceptance holds include G3 route/refresh integration, G4 page/event semantics, G5 operational custody/retention adapters, native hub runtime binding, served script convergence, signed receiver/provider/import acceptance, independent human review and separate production permission. Existing CI proof for G1/G2 does not close these. Production stays unchanged; Ads stay paused.
