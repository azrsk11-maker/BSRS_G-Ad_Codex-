# Offline keyword research controls

Negative research reviews must be dated on or after their source, claimed query observations and used metric evidence. Independent exclusion approval must also follow the research review and the eligible campaign context, applicable protected-query reviews and current scope verification. A later supporting review requires a new exclusion approval; an approval-only chronology hold preserves otherwise valid research while withholding approval. Invalid research chronology cannot count as reviewed or approved. The existing strict date-only format permits same-day equality; it does not prove ordering within that day. Protected-review dependency dates are indexed once per campaign, and invalid dates remain held. These checks do not authenticate reviewers, supply missing evidence or change actual master-library counts.

This is implemented development, not a completed14,000/14,000library or an Ads uploader. It uses Python's standard library and never makes a network request. Current `data/negative.json` contains **3,016 AI-reviewed research rows / 10,984 deficit for one proposed rental planning scope**, composed from 1,178 original, 935 employment and 903 academic/exam/vocational records; the positive master remains empty. Exclusion-approved and deployed counts remain zero, with independent human review pending. [Composed admission evidence and limits](../../docs/audit/keyword-negative-academic-admission-2026-11-11/README.md) distinguish research from serving instructions. Separate historical staging preserves [82 positive placements / 41 candidates](staging/historical-intake.json) and [27 negative placements / nine candidates](staging/historical-negative-intake.json), all unapproved with exact source provenance and no inferred metrics or current mappings. See [the intake report](../../docs/audit/KEYWORD_SEED_INTAKE.md). Synthetic fixtures exist only in test modules.

## Interchange and review model

`research.schema.json` defines a combined interchange envelope. CLI inputs are separate arrays: records (`.json` or `.csv`), sources, campaign context and protected queries. JSON and CSV duplicate keys/headers fail. Nested CSV scope/list fields contain JSON; empty measured-volume/CPC cells are null. Input is preserved; output contains validation diagnostics, not a rewritten master or platform-upload file. CLI refuses to overwrite any input. Keep approved evidence/private customer information out of public repository records; reference appropriately controlled evidence without copying its contents.

Every phrase retains original text and a computed NFKC/casefold/collapsed-whitespace key. A matching bracket/quote wrapper is excluded from uniqueness; language labels, match types and repeated placements do not create new phrases. Duplicate groups all fail pending reconciliation, so a preferred row is never selected silently. Placeholder, invisible/control-character and malformed-wrapper texts hold. Semantic/grammar/entity review remains human/evidence-dependent; the program does not invent a claim that lexical validation proves relevance.

Reviewed research rows require dated unexpired source evidence and review references. Observed versus hypothesis evidence remains distinct. Hypotheses carry explicit warnings; they are not measured demand. Missing volume/CPC stays null. Numeric metrics require their own provider/reference/date window; those references still need independent factual verification. Draft/rejected/held rows remain visible but do not count as reviewed. The research and approval stages are separate: a reviewed negative may count toward the research master while still **unapproved and undeployable**.

Positive ownership resolves a known campaign to its exact designated landing-page identity and requires an ad-group design key. Real platform IDs are never generated. Additional placements belong in a separate future placement register; repeating them in the master creates a duplicate failure. Broad research is allowed but explicitly held from deployment pending an approved experiment.

## Complete supplied-library coverage

`coverage_audit.py` implements Master §6's full supplied-positive and representative long-tail regression gate. For a negative audit, supply **both** `--positive-library` (the complete reviewed positive array, JSON or CSV) and `--coverage-review` (the dated independent review described by [the schema](coverage-review.schema.json)). This extends the existing CLI; it does not generate an approval or import historical candidates into a master. No real coverage certificate is supplied because the positive master remains empty and neither complete14,000-row business library is accepted.

The reviewer document must bind canonical SHA256 for all seven inputs: positive library, negative library, source registry, campaign registry, campaign context, protected corpus and scope bindings. `canonical_sha256()` hashes UTF-8 JSON with sorted object keys, compact separators and preserved array order; all values and extra fields are significant. The CLI also records raw file hashes, including the review document, from the same immutable bytes it parsed; a concurrent file edit cannot silently change that provenance. Ordered positive/query identity manifests prevent a silently omitted record from passing against the existing review. The document identifies an independent reviewer, evidence reference, valid date window, fixed matcher version and reviewed campaign/ad-group/page ownership. Hashes prove consistency, not that a human approval/reference is genuine; source authenticity and completeness of the owner's supplied inventory remain review obligations.

Every supplied positive must pass the existing research validation without filtering invalid, stale, duplicate, unreviewed or unmapped rows. Each needs at least one reviewed `LONG_TAIL` query with additional tokens and all original literal tokens, including repeated-token multiplicity. This is a minimum lexical counterexample requirement, not proof of real search demand or sufficient semantic diversity. `COUNTEREXAMPLE` queries can supplement it. The corpus adds `positive_ids`, `query_kind`, `source_id`, `source_reference`, `review_state` and `reviewer` to the existing dated protected-query fields. The exact campaign/service scope must match the linked positives' ownership and reviewed contexts. Duplicate IDs/text, missing links/sources, zero-token text, stale dates or missing evidence fail. Every campaign affected by a proposed negative must appear in the supplied positive library.

The simulator evaluates **all supplied positive literal phrases and all supplied protected queries** within each negative's declared eligible campaigns. Separate `POSITIVE_LITERAL` and `PROTECTED_QUERY` identities prevent collisions when IDs are equal. Campaign and token indexes avoid a blind all-pairs scan; the report records applicable pairs, actual lexical comparisons and index-pruned pairs. `AD_GROUP` uses the whole campaign conservatively and requires a known reviewed design group. Dated Real Estate account/campaign/group/shared-list scope bindings must pass the existing provenance checks; missing, wrong or stale mappings also hold coverage. Independently authenticating these evidence references, inspecting inherited negatives and checking actual live associations remain release obligations.

`evaluation_complete` means the exact supplied datasets passed provenance, freshness, mapping and completeness checks. `conflict_free_coverage_verified` and the audit's `positive_library_coverage_verified` require that **and zero scoped lexical conflicts**. Computed conflicts hold the affected negative regardless of approval text. Any attempted incomplete coverage audit clears approved-exclusion readiness and blocks structure acceptance; it does not manufacture reviewed research or platform approval. An absent coverage review leaves coverage unverified. A small complete fixture can pass this bounded proof while still failing the separate 14,000-row target. `deployment_export_allowed` and `production_writes_available` always remain false.

Run the focused modules with `python -B -m unittest -q test_coverage_audit.py test_keyword_audit.py test_historical_intake.py`. Tests include source/scope hash mutation, omissions, stale/duplicate/unmapped corpora, literal-only conflicts, namespaced IDs, cross-scope cases and an indexed-versus-brute-force parity oracle. The synthetic 1,000-negative × 2,000-case sparse test evaluates 2,000 lexical pairs rather than 2,000,000 applicable pairs; this is a deterministic operation count for that fixture, not a production speed or universal complexity claim. The historical41positive phrases remain unapproved staging candidates. Current master counts and scoped negative admission are recorded above; the synthetic coverage proof does not change them.
