3. Read live Ads account/configuration, dedicated GA4 stream and GTM published version without changes. Record current evidence separately from historical settings and drafting-pack nulls.
4. Inventory local source, deployment mechanism and permission gaps. Do not clone historical private data into this public repository. WP and Hostinger access must be authenticated before verifying installed source, staging/backups and rollback.
5. Establish protected main, feature PR, owner-decision issues, decision register, read-only CI and public-data hygiene. Verify enforcement and actual test results; report missing named checks/reviewer separation explicitly.

Exit: source-integrity evidence, audit findings, conflicts/issues, independent local tests, reviewed feature PR; unresolved live access is a dependency, not a reason to fabricate pass results.

## Phase 1 — Local foundation and research system

1. Build a native-page planning compiler. Every proposed campaign owns one primary entry page; pages remain planning slots until distinct reviewed evidence/content exists. Validate ID/path uniqueness and existing-route conflicts. Compile a dry-run manifest, not 360 published pages.
2. Implement positive/negative research ingestion and normalization. Record exact original phrase, canonical text, primary campaign, intent, language, geography, source and dated review. Match variants/placements do not inflate distinct phrase counts. Reject padding and invalid evidence. Keep research/validated/approved/exported/deployed counts separate.
3. Implement scoped negative simulation against protected commercial queries. Account-wide exclusions require the strongest evidence; campaign/ad-group exclusions must not suppress relevant rental, affordable, owner, occupier or research intent. Unapproved conflicts prevent export.
4. Implement a local tracking contract adapter and adversarial payload/dedup tests. Preserve immutable accepted receipt → one mapped event; retain private correlation only internally. Never infer answered calls, received WhatsApp messages, confirmed bookings, qualification, a transaction or collected commission from a click.
5. Implement approval gates, test-evidence ledger and read-only commercial calculations using synthetic fixtures. Costs/revenue remain unknown until authorized evidence exists; property sale price is not brokerage revenue. No production financial writes.
6. Use three independent workstreams with separate output ownership, one browser operator. Reuse source hashes and cached log summaries; run targeted tests for changes. Do not claim audit microbenchmarks as overall token savings.

Exit: tested offline artifacts and a PR; no live integrations implied. Exact research masters remain incomplete until all evidence-bearing phrases have actually been researched and reviewed.
