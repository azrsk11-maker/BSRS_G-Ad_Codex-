# Rejected test fixture reuse experiment

No optimization was retained. A temporary change to `NegativeLibraryTests.setUpClass` supplied detached copies of its freshly constructed first and employment cohorts only while assembling its historical library fixture. Every later public verification, freshness and tamper call remained real. The fixture source was restored exactly after measurement.

Four sequential setup measurements used ABBA order in one local process: before 11.836664 / 15.062964 seconds; candidate 13.350796 / 13.496559 seconds. Medians were 13.449814 and 13.4236775 seconds respectively: a 0.0261365-second difference, about 0.194326 percent, with overlapping observed ranges and uncontrolled host/cache effects. This does not establish a useful speed gain. The constructor-call reduction alone did not justify retaining scoped mocks and deep-copy overhead. The four setups totaled 53.746983 seconds, within the 120-second measurement budget.

The diagnostic loaded the committed and temporary test modules separately, wrapped the real upstream constructors to count calls, and compared complete canonical `inputs`, `initial` and `second` bodies across all four setups. All bodies matched; calls fell from two to one per upstream constructor in the candidate. Mutating the assembled fixture and a downstream copy preserved the upstream originals. The candidate's already-loaded class then ran all 29 existing tests, including source tamper and cross-invocation freshness checks: zero failures/errors/skips in 153.979329 seconds, with complete first/second bodies unchanged afterward. No second unchanged class run is claimed.

The [receipt](receipt.json) records timings, full-body digests, call counts, assertion results and rejection. This experiment supplies no Foundation result, current-library acceptance, public acceptance cache, timeout change or whole-suite/token/API/billing savings claim. Original tests and all production validators remain unchanged.
