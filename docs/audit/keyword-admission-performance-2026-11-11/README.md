# Measured local validator improvement

For the same **2,113-record** source, data, review and report inputs on this Windows environment, three sequential trials per implementation measured median validation time **3.937628 → 2.344616 seconds**, a **40.46% reduction**. All six results have the same canonical SHA256. Pinned reads fell from **121 to 52** and cohort reconstructions from **five to two per invocation**. [Measurements, individual trials and snapshot hashes](measurements.json).

The original implementation independently verified both cohorts and then reconstructed them again for the aggregate. The change reconstructs each cohort once within the current invocation and passes those freshly pinned inputs through the same cohort audit/report checks and whole-master validation. Standalone cohort entrypoints still reconstruct their own inputs. There is **no persistent or cross-invocation cache**; changed sources after a previous successful run are still read and rejected.

These measurements were taken **before adding the third academic cohort**. They are local, sequential, instrumented timing observations, not cold-cache, whole-workflow, provider-token, API, billing or production-performance savings. Wrapper counters were present in both versions. The larger current dataset is a different workload and must not be compared as if its inputs were identical.

The byte-equal public baseline is feature commit `1e865e15243b518e8cb3a915f11d116f6294d5cf`, local `ae690126616214676774f5bcce8c7bf7283ad2ce`. The small [source-only optimization patch](optimization.patch) and its hash preserve the exact three-module optimized snapshot used for measurement. This is historical audit evidence: **do not apply it to the current expanded tree**. Reproduction requires a separate reviewed feature checkout of that baseline and the same unchanged 2,113-record inputs. Run three timed `negative_library.verify()` calls with `time.perf_counter()`, wrap the two cohort `reconstruct` functions and shared `pinned` reader with `unittest.mock.patch(..., wraps=...)`, and compare canonical result hashes before and after applying the reviewed patch in that disposable checkout. No dependency install or platform operation is required.

Current regression coverage additionally checks one reconstruction per registered cohort, fresh original and new source reads after previous success, original published record bytes, expiry/authority controls and full-master tampering. The optimization changes no research, exclusion approval, production authorization, source facts or deployment settings. Current combined acceptance is recorded separately in the PR handover.
